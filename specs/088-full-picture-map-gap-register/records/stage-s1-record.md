## Departures, stated plainly

(a) **Membership rule clarified against the draft's
premise.** The taxonomy draft recorded "a claim belongs to
exactly one study" with none multi-spec today; the plan's
S1 text phrases membership as "any of its `sources[]`
carries `spec` == S". On the post-adoption ledger that
premise is false: **44 bundle claims name more than one
distinct spec directory across their sources** (in
non-representative roles — `bundle_aee`,
`evidence_instance`, `promotion`). The defs as filed
register membership = the **source-of-record** source's
spec only (verified: all 853 bundle claims have exactly
one source-of-record source, it always carries a `spec`,
and it always equals the first spec-carrying source); the
44 are enumerated in every build's coverage block so the
default is visible. Counting citations as membership would
let a citing study's class move with claims it did not
produce. If the owner wants the any-source rule instead,
it is a defs amendment (v2) plus a builder change — the
record names the fork rather than burying it.

(b) **Census numbers moved by recomputation, as the plan
directs.** The package/plan census (857 claims / 88
studies) predates the T004 adoption intake; the live
inputs give 876 / 89 / 28. The conformance test recomputes
from the raw inputs and pins the live census; T104's task
text carries the old figures and its own instruction that
the census is "recomputed from the inputs at test time".

(c) **Artifacts generated and verified, not committed.**
Per the plan's staging, the first committed
`program-map.json` / `program-map-finds.json` are S2's
T201. S1's determinism + `--check` proofs ran over a
scratch copy of the inputs; the conformance test therefore
deliberately does not run check semantics against the real
root (they would read as drift until S2 lands the files).

(d) **T303's writer registration pulled forward one line.**
With the builder present, the Spec 086 gate's V9 writer
census FAILS on the real tree: the census flags any
write-call module whose text references `glossa-indus/map`,
and `program_map_generate.py` is exactly that (first
observed: `test_gate_passes_clean_tree` +
`test_v9_census_names_the_map_writer_on_the_real_tree`
failing, gate 19 PASS / 1 FAIL / 1 NOT-RUN with
"UNREGISTERED WRITER: backend/glossa_lab/
program_map_generate.py"). The plan stages the
registration at T303 (S3), but an S1 PR cannot land with a
red gate, and V9's invariant — the registered generator
and the gated-publication path are the only writers — is
upheld, not weakened, by registering the sanctioned
generator. So `backend/glossa_lab/program_map_generate.py`
was added to `REGISTERED_WRITERS` in `ledger_gate.py` in
this stage, with a comment saying so. Nothing else about
the gate changed: V10 (the independent recompute class),
T303's artifact-pattern confirmation (the existing
`glossa-indus/map` prefix pattern already covers the
program-map paths), and T303's negative case remain S3's,
exactly as planned.

(e) **Directory name.** The spec lives at
`specs/088-full-picture-map-gap-register/`; the plan text
occasionally says `088-program-map-gap-register`. The
