Program status

One screen that answers "where does the program stand" entirely from records: gate results, loop state, census, and the blocked list with owners. Serves protocol step 2 (establish what the system claims and does not claim) together with the home's does-not-claim panel.

Gate and loop state (left, primary)

  • Foundation check result (17 checks) with its run time.
  • Ledger gate summaries: full profile, regeneration profile, contamination class — the recorded numbers, not a paraphrase.
  • Research-loop state: running or idle, current study, last adjudication. Read from the loop's own status surface.
sources: MCP foundation check; tools/ledger gate records; research-loop status API

Blocked and waiting (right rail)

  • Each blocked item named with its blocker and its owner (a person or a system), in the program's standing report form.
  • Owner-gated items are labelled as such (wireframe approvals, session proofs, sends).
source: goal PROGRAM-STATE record; gap register (glossa-indus/map/gap-register.md)

Census of record

Claims, studies, anchors by standing, corpora by identity status — the same numbers as the home band, with the as-of commit for each.

sources: claims ledger; INDUS_FINAL_ANCHORS.json; corpus identity registry

Recent landings

Latest merged stages with their verdicts (wrapper and payload numbers both, per the program's reporting rule).

source: spec records under specs/*/records/

Interactions

  • Every number drills into the surface that owns it (census → evidence inspection; gate state → the recorded gate output).
  • Refresh re-reads the records; nothing is cached into a second, divergent status.

This surface refuses to

  • Infer progress ("on track", percentages complete) that no record states.
  • Show a status for a job from its wrapper's completion alone; the payload verdict is the status.
  • Hide a failed or blocked item below a summary line.
