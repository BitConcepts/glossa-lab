Purpose
Point 5's system view: the decipherment model as a whole — sign inventory by frame with the incumbent run's assignment state, where the load sits (conflict and zero-coverage hotspots from the matrix coverage block), and the claim population by status and stage. All numbers on this screen are the real current numbers from the merged ledger/matrix/settling artifacts, not specimen data — the owner approves the real header, not a mock.
Primary action
Read the program's whole state in one screen, then drill down: a claim row in the matrix view opens the claim view; a column behind it opens the evidence view.
Changed & why
Against Spec 085's 01 explorer: the node-link canvas is removed (decision Q1). The gated chain has no claim-graph edge set to draw — the 790 claim×claim dependency pairs are coverage data, not verified cells — so a canvas would present a picture the gate does not check. What replaces it is the inventory/coverage/population composition Point 5(c) specifies. Against today: no System graph screen exists in the app at all — the nav entry is new, and the nearest current screens (Claims, Data, Analysis) each show one kind of thing at a time. The header strip is new on every screen of this surface (T501 delta) and carries the as-of stamp line with its STALE behavior (C086-18).
