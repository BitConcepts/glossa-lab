Annotation — wireframe 04 · not part of the UI
Purpose
The generated claims×evidence matrix as the surface's primary grid (T501 delta): the shape of what bears on what, with every cell's citations inspectable and every absence rendered as itself. Rows, columns, and cells in the specimen are the artifact's real contents, abridged only by paging, which the screen names.
Primary action
Filter by column class, relation, or sign reference; select a cell to read its citations and the rule that derived it; open a row into the claim view.
Changed & why
Against Spec 085's 02 matrix view: the primary form changes from claim×sign incidence to claims×evidence (the 085 default is superseded — there are no claim×sign cells in the generated matrix at all, because the ledger's identifier-based sign_refs resolve to register records, not evidence columns; claim×sign survives as the sign row-filter, decision Q5). The 085 heatmap shading by edge weight is gone: cells carry their relation as a word, because a shade cannot show which of three relations a cell is, and constrains (0 cells) must be statable. The unused-class grey columns are new — 085's matrix had no wholly-unused column class to render. Against today: no matrix is served or shown anywhere in the app.
Spec claims
C086-17 (rendered counts and elements equal the gated artifact for the same selection — T504 verifies by Playwright capture against this wireframe), C086-19 (a scoped rendering contains no out-of-scope element and no relation incident to one). The screen renders the artifact; it does not compute, so a rendering defect is a downstream defect, fixed by correction of the surface — never by editing the artifact (Point 6).
