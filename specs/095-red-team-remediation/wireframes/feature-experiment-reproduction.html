Experiment reproduction

Reproduce one published result (protocol step 5): choose the result, read the execution that produced it, re-run the same experiment, and compare — run by run, never pooled.

1 · Choose a published result

  • Results listed by study and claim, each with its verdict of record and its does-not-establish bound.
  • A result whose execution record is incomplete is listed as not reproducible, with the missing piece named.
sources: spec records; run index (Spec 089 discipline)

2 · The execution of record

  • Inputs by hash, corpus by identity (verified before anything runs), environment, seeds, code identity.
  • The full attempt accounting for the original run: every attempt, including negative ones.
sources: execution records; corpus identity registry (fail-closed verification)

3 · Re-run and compare

  • The re-run executes against scratch stores in the researcher's own workspace, never against live program stores.
  • Comparison is per-quantity, original run beside re-run, divergences named with their size.
sources: the experiment's own entry points; workspace-scoped stores

Interactions

  • Any divergence opens the differing input or step, not a generic "results differ" notice.
  • A completed reproduction can be attached to the claim as evidence, typed as a reproduction, through the contribution surface.

This surface refuses to

  • Run anything against a corpus whose identity does not verify.
  • Pool or average results across runs; comparison is run against run.
  • Re-run against live stores, or write a reproduction outcome into a claim's standing directly (standings change only by adjudication).
  • Call a result reproduced when any input hash differs from the execution of record.
