First-run setup

This deployment has no users yet. This screen creates its one administrator account — and then it closes, permanently. It can be completed only with the one-time setup code from the deployment terminal.

SPECIMEN-CODE-SHOWN-ONCE

In the real flow the owner pastes the code here; nothing about it is ever sent by email or chat, and it stops working 24 hours after it was issued.

Once, only. When this account exists, this page is gone — there is no second setup and no back door. If the code expires unused, the operator issues a new one from the deployment side.

glossa.bitconcepts.tech · Setup is part of the deployment record: its completion (not the code, not the password) is written to the audit log.

Annotation — wireframe 03 · not part of the UI
Purpose
Seed the glassbreak admin exactly once, with a password that exists only in the owner's head and as a salted hash in D1 (FR-003). No password crosses chat, code, configuration, or logs at any point in the flow — the code is a capability, not a credential for the account itself.
Primary action
“Create the admin account”.
Changed & why
New surface, and the security keystone of the edition: every later account descends from invites this admin issues, so the root of trust is this one screen. The username field arrives pre-filled with the owner's chosen name and stays editable here (setup is the one moment it can be set); after setup, usernames are immutable (wireframe 08). The specimen code is labelled as such — a real code never appears in any document.
Spec claims
C083-3 (seeding — single-use code, 24-hour expiry, permanent closure, no password material anywhere), C083-12 (completion is audit-logged), C083-14 (this runs on staging first).
